# Ownership

In the age of AI, agents, and LLMs, the sense of ownership is changing.

It feels like the paradigm shift has already happened. Code used to *be* ownership — mostly because you wrote it yourself, and it was deeply personal. So what happens to ownership when an agent writes the code for you? I think ownership shifts, and not always for the better. There's now an easy out: you can always blame the agent for screwing things up and make it the scapegoat when things go south.

Some people believe that critically interrogating the coding agent — asking it hard questions — can restore a sense of ownership. I think that's a false sense of it, closer to AI psychosis than to real understanding. We forget too easily that agents are just a bunch of tokens, probabilistically cobbled together. Tell an agent it's wrong and it changes its opinion. Tell it to give up and it accepts defeat. Conviction borrowed from a machine isn't conviction at all.

So what does real ownership look like? I believe it comes down to three things:

1. **Attention to detail.** The creator obsesses over the minutiae — the UI, the code, the architecture. The small things nobody else notices.
2. **Root cause analysis.** Knowing the possible error patterns and what each one likely maps to in the codebase. Having a gut feel the moment you see an issue for what it probably is.
3. **Absolute understanding of how it works.** If a colleague asks you about a feature and how it works, you can answer — completely, without hand-waving.

This is no longer about being a senior, junior, or staff engineer. In the age of AI, every engineer is a product owner. Everyone is expected to figure this out, and everyone should be aligned.
